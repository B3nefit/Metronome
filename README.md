# StageClick — 공연용 안드로이드 메트로놈

인이어로 클릭을 들으며 연주하는 라이브 공연용 메트로놈입니다.
외부 라이브러리 없이 안드로이드 기본 API만 사용하며, **인터넷 권한이 아예 없는 완전 오프라인 앱**입니다.

- 최소 사양: Android 8.0 (API 26) 이상
- 언어: Kotlin / 순수 안드로이드 View (Compose·AndroidX 미사용 → 가볍고 빌드가 단순)

## 요구사항별 구현 내용

| # | 요구사항 | 구현 |
|---|---|---|
| 1 | 여러 세트리스트 | 세트리스트 무제한 생성·이름변경·복제·삭제. 곡 추가/편집/복제/순서이동. JSON 내보내기·가져오기(백업, 멤버 간 공유) |
| 2 | 버튼 지연 없음 | 모든 버튼이 **손가락이 닿는 순간(ACTION_DOWN)** 동작. 오디오 스트림을 항상 열어 두어(웜 스트림) START 후 다음 오디오 버퍼(수 ms) 안에 첫 클릭 출력. 시스템 터치음 비활성화 |
| 3 | 오프라인 | 인터넷 권한 없음. 클릭음은 앱이 직접 합성, 데이터는 기기 내부 JSON 저장 |
| 4 | 공연용 UI | 검정 배경·고대비, 대형 BPM·START 버튼, 박 원 표시 + 화면 플래시, 곡 메모 표시, **🔒 잠금 모드**(START/STOP만 동작), 화면 꺼짐 방지, 전체화면 |
| 5 | 가로/세로 | 세로: 위 컨트롤 + 아래 곡 목록 / 가로: 왼쪽 컨트롤 + 오른쪽 곡 목록. 화면 크기에 맞춰 글자·버튼 크기 자동 조절. **회전해도 재생이 끊기지 않음**. 방향 고정 옵션 |
| 6 | 시끄러운 환경 | 밴드 소리가 몰린 저·중역을 피해 귀가 가장 민감한 2~4 kHz 대역 클릭, 날카로운 어택. 소리 5종, 부스트 최대 +12 dB(소프트 리미터로 찌그러짐 없이 체감 음량↑), 강박/약박/분할음 음높이 차등 |
| 7 | 안드로이드 | Android 8.0+ 저지연 AudioTrack(FAST 경로) |
| 8 | 인이어 | 출력 채널 선택(양쪽/L/R), 이어폰·송신기 케이블 분리 시 자동 정지(관객 쪽 스피커로 새는 것 방지), 스피커 출력 시 빨간 경고 |
| 9 | 유선/무선 옵션 | 출력 방식 3종 — **유선 / 무선 IEM 송신기 / 블루투스** (아래 상세) |

### 9. 출력 방식 옵션이 실제로 하는 일

| | 유선 | 무선 IEM 송신기 | 블루투스 |
|---|---|---|---|
| 휴대폰 오디오 버퍼 | 최소 (버스트 2개) | 최소 (버스트 2개) | 넉넉하게 (≥ 40 ms, 끊김 방지 우선) |
| 화면 보정 기본값 | 0 ms | +4 ms (디지털 송신기 평균) | 탭 보정 권장 |
| 기타 | — | 아날로그 송신기용 '클릭 길이: 길게' 권장 | 스트림 상시 유지로 첫 박 잘림 방지 |

- **템포 정확도는 세 모드 모두 동일**합니다(샘플 단위). 지연이 영향을 주는 것은 ① START를 누른 뒤 첫 클릭이 들릴 때까지의 시간, ② 화면 깜빡임과 소리의 일치, ③ 끊김 위험입니다.
- 출력 방식마다 **화면 보정값을 따로 저장**하므로, 유선 ↔ 블루투스를 오가도 다시 맞출 필요가 없습니다.
- 블루투스가 연결되면 자동으로 블루투스 모드, 케이블을 꽂으면 직전 유선 모드로 돌아갑니다(설정에서 끌 수 있음).
- 설정 › 오디오 상태에서 **실제 측정된 출력 지연(ms)**, 버퍼 크기, FAST 경로 사용 여부, 끊김 횟수를 볼 수 있습니다.
- **🎯 탭 보정**: 60 BPM 클릭에 맞춰 패드를 8번 이상 탭하면, 귀에 들리는 시점과 화면 표시를 자동으로 맞춥니다.

> 블루투스는 구조상 100~300 ms 지연과 순간 끊김 위험이 있어 공연에는 **유선 또는 무선 IEM 송신기(케이블로 폰과 연결)** 를 권장합니다.

## 빌드 방법

### A. Android Studio (가장 쉬움)
1. Android Studio 설치 (Ladybug 2024.2 이상)
2. `File › Open` → 이 `StageClick` 폴더 선택 → Gradle 동기화가 끝날 때까지 대기
3. 휴대폰을 USB로 연결(개발자 옵션 › USB 디버깅 켜기) → ▶ Run
4. 설치 파일만 필요하면: `Build › Build App Bundle(s) / APK(s) › Build APK(s)`

### B. GitHub Actions (PC에 아무것도 설치하지 않고 APK 받기)
1. 이 폴더를 GitHub 저장소에 올립니다 (`.github/workflows/build-apk.yml` 포함)
2. 자동으로 빌드가 돌고, **Actions 탭 › 최근 실행 › Artifacts › StageClick-apk** 에서 APK를 받습니다
3. 휴대폰으로 APK를 옮겨 설치 (출처를 알 수 없는 앱 설치 허용 필요)

### C. 명령줄
```bash
./gradlew assembleRelease        # → app/build/outputs/apk/release/app-release.apk
./gradlew testDebugUnitTest      # 타이밍 정확도 테스트
```
release APK는 바로 설치할 수 있도록 디버그 키로 서명됩니다. Play 스토어에 올리려면 본인 키스토어로 바꾸세요.

## 사용법

- **START/STOP**: 큰 녹색/빨간 버튼. 닿는 순간 동작
- **◀◀ / ▶▶**: 이전/다음 곡. 재생 중에 누르면 멈추지 않고 다음 박부터 새 곡의 템포·박자로 이어짐(메들리용)
- **−5 −1 TAP +1 +5**: 템포 조절(길게 누르면 연속). TAP은 2번 이상 두드리면 평균 템포 적용
- **BPM 숫자 터치**: 직접 입력(소수점 1자리, 20~400)
- **제목 터치**: 곡 편집
- **박 원 터치**: 강박(주황 테두리) → 보통 → 무음(X) 순환
- **곡 목록**: 터치 = 선택(정지 중), 길게 = 메뉴(편집·이동·복제·삭제·재생 중 즉시 전환)
- **📋 세트리스트 이름**: 세트리스트 전환 / 새로 만들기 / 관리(내보내기·가져오기)
- **🔒**: 잠금. 잠금 중엔 START/STOP만 동작, 자물쇠를 **길게** 누르면 해제
- **카운트인**: 곡마다 0~4마디. "카운트인만 주고 정지"를 켜면 카운트 후 클릭이 자동으로 꺼짐
- **정지 시 다음 곡 자동 선택**(기본 켜짐): 곡이 끝나고 STOP을 누르면 다음 곡이 준비됨
- **블루투스 페달/키보드**: Space·Enter = 시작/정지, ←/→·PageUp/PageDown = 이전/다음 곡

### 공연 전 체크리스트
1. 휴대폰 **방해 금지** 켜기 — 알림음이 인이어로 섞이지 않게
2. 설정 › 소리 › **터치음·키보드음 끄기**
3. 휴대폰 미디어 볼륨은 최대 근처, 실제 크기는 송신기/벨트팩/앰프에서 조절(잡음 대비 신호가 좋아짐)
4. 절전 모드 끄기, 이 앱을 배터리 최적화에서 제외
5. 앱을 켜고 오른쪽 위 출력 표시가 `🎧 유선`/`🎧 무선 IEM`인지 확인 (빨간 `⚠ 스피커`면 연결 안 됨)
6. 무대에서는 🔒 잠금

## 구조

```
app/src/main/java/com/stageclick/metronome/
├── audio/
│   ├── ClickScheduler.kt   샘플 단위 스케줄러 (순수 Kotlin, 드리프트 없음)
│   ├── ClickSounds.kt      클릭음 합성 5종
│   ├── ClickEngine.kt      저지연 AudioTrack, 웜 스트림, 버퍼 자동 조정, 타임스탬프
│   └── TickRing.kt         오디오 → UI 이벤트 전달 (할당 없는 링버퍼)
├── data/
│   ├── Model.kt            곡 / 세트리스트 / 설정
│   └── Repository.kt       JSON 저장, 내보내기/가져오기
├── ui/Widgets.kt           즉시 반응 버튼(PadButton), 박 표시(BeatView)
├── MainActivity.kt         메인 화면 (가로/세로), 화면-소리 동기화, 페달 입력
├── Dialogs.kt              곡 편집, 세트리스트, 설정, 탭 보정
├── PlaybackService.kt      재생 중 포그라운드 서비스 (홈/전원 버튼에도 끊기지 않음)
└── App.kt                  앱 전역 상태, 이어폰 분리 감지, 출력 장치 판별
```

### 타이밍 설계
- 오디오 스레드가 블록마다 `render()`를 호출하고, 클릭은 블록 안의 **정확한 샘플 위치**에 놓입니다.
- 박 위치 = 기준점 + n × 간격 으로 계산 → 몇 시간을 틀어도 누적 오차 0 (1 샘플 = 0.02 ms 이내).
- UI는 명령 큐로만 엔진을 제어 → 오디오 스레드는 락을 기다리지 않음.
- 화면 표시는 `AudioTrack.getTimestamp()`로 "이 샘플이 실제로 출력되는 시각"을 계산해 소리와 맞춥니다.

### 검증된 것 / 실기기에서 확인할 것
- ✅ 스케줄러 단위 테스트 11종 통과: 1시간 재생 시 오차 ≤ 1샘플(120·133.3·97.5·61·240 BPM), 버퍼 크기와 무관한 동일 타이밍, 카운트인·분할·무음 박·템포 변경·곡 전환, 리미터 클리핑 없음, START 후 다음 블록 첫 샘플에서 즉시 클릭
- ✅ 전체 소스가 Android API 34 기준으로 경고 없이 컴파일됨
- ⚠ 실제 휴대폰에서의 체감 지연·음량·레이아웃은 기기마다 다르므로 리허설에서 꼭 확인하세요 (설정 › 오디오 상태의 측정 지연 참고)
